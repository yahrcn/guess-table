# Угадай персонажа

Браузерная онлайн-версия игры «Угадай кто» на двоих: поле 5×5 карточек, приватный выбор секретной карточки, вопросы да/нет по очереди, личное вычёркивание неподходящих карточек и финальная догадка. Доступ в комнату — по прямой ссылке, без матчмейкинга.

## Стек

- **Клиент:** React + Redux Toolkit (слайсы + redux-saga) + CSS Modules + Vite + Socket.IO client
- **Сервер:** Node.js + Express + Socket.IO
- **Монорепо:** npm workspaces (`packages/shared`, `packages/server`, `packages/client`)

## Наборы карточек

Шесть наборов по 25 карточек — выбирает создатель комнаты в лобби, пока ждёт второго игрока (см. [`cards.ts`](packages/shared/src/cards.ts)):

- Вымышленные персонажи
- Известные личности (только давно умершие исторические фигуры — никаких вопросов о праве на изображение живых людей)
- Животные
- Профессии
- Фильмы
- Видеоигры

Для «Известных личностей», «Фильмов» и «Видеоигр» используются только текстовые названия/имена — ни одной реальной фотографии, обложки, кадра или логотипа в приложении нет и не подгружается. Иллюстрация на карточке — всегда SVG, сгенерированный на лету детерминированно по `seed` карточки: для людей (вымышленные персонажи, известные личности, профессии) это условное лицо (`Avatar`), для животных — условная морда (`AnimalAvatar`), для фильмов/видеоигр — абстрактная «плитка» с геометрией, разной для каждого из этих двух наборов (`MediaAvatar`). Выбор генератора под набор — в [`DeckAvatar.tsx`](packages/client/src/components/Room/components/DeckAvatar/DeckAvatar.tsx).

Добавить новый набор: добавить значение в `DeckId`, 25 карточек в `CARD_DECKS` и подпись в `DECK_LABELS` (`packages/shared/src/cards.ts`), при необходимости — завести под него отдельный генератор иллюстраций и прописать в `DeckAvatar`. Подставить реальные фото вместо генерируемых иллюстраций: добавить `imageUrl` в `Card` и отрендерить `<img>` вместо `<DeckAvatar>`.

## Структура

```
packages/
  shared/   # общие типы, контракт socket-событий, колода карточек, нормализация вопросов
  server/   # Express + Socket.IO, игровая стейт-машина комнаты (RoomManager/Room)
  client/   # Vite + React + Redux Toolkit
    src/
      entries/App        # корневой компонент SPA
      config/             # store, корневой редьюсер/сага, типизированные хуки
      pages/              # тонкие роуты (HomePage, RoomPage) — без логики
      components/
        Home/             # фича «создать комнату»: slice + selectors + sagas + UI
        Room/             # фича «игра в комнате»: slice + selectors + sagas + UI + components/*
      shared/
        components/       # переиспользуемые UI-куски (Button)
        session/          # личность игрока (playerId/token/roomId) — сквозной слайс
        helpers/          # localStorage-хелперы
        socket/           # Socket.IO клиент и типизированные запросы
```

Код фронтенда следует конвенциям из `billy-frontend-code-style`: слайсы redux-toolkit с фабриками `create[Имя]State`, экшены вида `fetch/select/ask/answer/finalGuess[Begin|Success|Error]` с объектным payload'ом, вся сетевая логика — в сагах (а не в `useState`/прямых вызовах из компонентов), строковые enum'ы (`Phase`, `FinishReason`, `AsyncStatus`, `ConnectionStatus`), `cx`/`classnames` для условных классов, страницы — тонкие обёртки над «фичами» в `components/`. Инфраструктурно-специфичные для Контура правила (react-ui, `@skbkontur/icons`, `@skbkontur/colors`, сгенерированные api-клиенты, `Url.Action`, `ErrorBoundary`-HOC) не применялись — этих пакетов в проекте нет, а `connect()`/`Container`-обёртка не нужна, так как подключение к стору всюду через хуки (`useAppSelector`/`useAppDispatch`), без динамической инжекции редьюсеров.

## Запуск локально

```bash
npm install
npm run dev
```

Поднимутся:
- сборка `shared` в режиме watch,
- сервер на `http://localhost:4000`,
- клиент (Vite) на `http://localhost:5173` (dev-сервер проксирует `/socket.io` на сервер).

Откройте `http://localhost:5173` в двух разных вкладках (одна — в режиме инкогнито, чтобы не делить localStorage), в одной нажмите «Создать игру», скопируйте ссылку на комнату и откройте во второй.

## Сборка и запуск в продакшен-режиме

```bash
npm run build   # соберёт shared -> client -> server
npm start       # запустит собранный сервер; он же отдаёт клиентскую статику
```

В продакшене один Node-процесс слушает один порт: отдаёт и собранный клиент (`packages/client/dist`), и WebSocket (Socket.IO) — поэтому не нужен отдельный хостинг под фронтенд и не нужно настраивать CORS.

## Чеклист деплоя (Timeweb Cloud)

Используем [Timeweb Cloud Apps](https://timeweb.cloud/docs/apps) — он запускает произвольный Node.js-процесс и умеет WebSocket (в отличие от обычного shared-хостинга). Разворачиваем **одно** приложение: в проде Express-сервер сам раздаёт собранную React-статику и держит Socket.IO на одном порту — отдельного «React-приложения» заводить не нужно.

1. Запушить репозиторий на GitHub (или GitLab).
2. В Timeweb Cloud создать новое приложение, подключить репозиторий.
3. На шаге выбора типа/фреймворка выбрать **Express** (Node.js), не React — React в проде обслуживается тем же Express-процессом через `npm run build`.
4. **Корневая директория (root):** оставить пустой (не указывать) — она нужна только для монорепо с проектом в подпапке, а нам, наоборот, нужна сборка из корня, где лежит `package.json` с workspaces.
5. **Команда установки/build command:** `npm install --include=dev && npm run build` — именно `--include=dev`, а не просто `npm install`. Переменная `NODE_ENV=production` (см. ниже) иначе заставит npm пропустить все `devDependencies` (`typescript`, `vite`, `tsx`) прямо на шаге установки, и сборка упадёт с `tsc: not found`.
6. **Start command:** `npm start`
7. **Версия Node.js:** любая современная LTS (20/22/24).
8. **Переменные окружения:** `NODE_ENV=production` (порт платформа обычно пробрасывает через `PORT` — сервер уже читает `process.env.PORT`).
9. Убедиться, что в настройках приложения включена поддержка WebSocket/долгоживущих соединений (должно быть по умолчанию для Cloud Apps).
10. HTTPS включается платформой автоматически — Socket.IO сам переключится на `wss://`.
11. Открыть выданный URL в двух вкладках/окнах (одно — инкогнито), создать игру в одном, скопировать ссылку на комнату, открыть во втором — пройти полный цикл партии.
12. (опционально) подключить свой домен, настроить мониторинг логов платформы.

> Точные названия полей в мастере создания приложения могут отличаться от описанных выше — ориентируйтесь по смыслу (тип/фреймворк, корневая директория, build/start-команды, переменные окружения). Любой другой PaaS с поддержкой произвольного Node.js-процесса и WebSocket (Render, Fly.io, Railway, Amvera) разворачивается по той же логике.

## Правила, зашитые в сервер

- Каждая комната рассчитана ровно на двух игроков; третий получит ошибку «комната заполнена».
- Секретная карточка каждого игрока хранится только на сервере и никогда не попадает в снимок состояния оппонента.
- Повторный одинаковый вопрос в рамках одной партии отклоняется сервером (сравнение после `trim` + нижний регистр + схлопывание пробелов/пунктуации — см. [`normalizeQuestion`](packages/shared/src/normalizeQuestion.ts)).
- Неверная финальная догадка не завершает партию: угаданная карточка навсегда блокируется у игрока (её нельзя ни кликнуть повторно, ни снять с исключения вручную — в отличие от обычных личных пометок), а ход переходит сопернику. Побеждает только тот, кто назвал карточку верно.
- При разрыве соединения игрок не исключается из партии: переподключение по сохранённому в `localStorage` токену восстанавливает его место в той же комнате (на клиенте это отдельная сага, слушающая переподключение сокета — см. [`components/Room/sagas.ts`](packages/client/src/components/Room/sagas.ts)).
- Неактивные комнаты (без действий более 2 часов) удаляются из памяти сервера.
- «Сыграть ещё» (`game:rematchBegin`) сбрасывает партию в той же комнате — новая перетасовка поля, секреты и лог вопросов очищаются — но только после того, как оба игрока подтвердят готовность (набор карточек при реванше остаётся тот же, что был выбран изначально).
- Набор карточек (`game:selectDeck`) может сменить только первый игрок в комнате (создатель) и только пока она в статусе «лобби» — после входа второго игрока фаза лобби сама заканчивается и выбор блокируется.

## Известные ограничения MVP

- Состояние живёт в памяти процесса — при перезапуске сервера все активные партии теряются (достаточно для single-instance деплоя из чеклиста выше; для горизонтального масштабирования понадобится вынести состояние в Redis).
- Нет автотестов — логика проверялась вручную по сценарию из раздела «Запуск локально».
- «Сыграть ещё» требует согласия обоих игроков (оба должны нажать кнопку после завершения партии) — если один из них закрыл вкладку насовсем, реванш в этой комнате так и останется в ожидании.
